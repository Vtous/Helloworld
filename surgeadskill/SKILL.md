# surgeadskill

完成链路：确认目标 → 连接手机 → 记录无操作对照和广告窗口 → 提取候选 → 逐条临时拦截和回退验证 → 更新规则源及生成文件 → 手机刷新复测 → 清理临时改动。

## 本用户约定

- 默认仓库 `Vtous/Helloworld`、分支 `main`；规则叫 **adgoaway.list**，不是 adgoway.list。
- 持久规则源是 `sources/rules.json` 的 `local.adgoaway`；只手改生成列表会被同步流程覆盖。
- 默认不启用 MITM，不安装证书，不启用 HTTPS 重写或脚本。手机原有 Surge 继续接管流量。
- 主配置保留中文备注，策略菜单平铺；不要添加 category、改分组顺序、出口、DNS 或节点。
- 公共仓库只放规则和必要的非敏感说明；控制密码、订阅、证书、HAR、原始请求、截图、实验记录均留在仓库外。
- 域名/IP 规则会影响所有使用它们的 App；iOS 的 PROCESS-NAME 不能实现按 App 隔离。

## 1. 确认范围和接管实例

确认 App 名、广告入口（冷启动/弹窗/自动拉起其他 App）、手机是否可操作。能从当前对话和连接信息获得的，不重复问。缺少 App 名或设备操作时先询问，继续准备独立步骤。

先读 [连接和观察](references/connection.md)。优先用 Mac Surge Dashboard 经 USB 连接手机 Surge。Mac 本机请求不是手机请求；`--remote` 指向手机后才可用远程 CLI。需要用户解锁、信任电脑或打开目标 App 时明确交接，等待真实结果。网络管理接口不能替代手机点按控制。

只读取当前版本、出站模式、MITM/抓包状态、过滤器、临时规则、adgoaway 订阅状态和最近请求。记录准备改动的原值。已有授权足够时继续必要的可逆操作，不反复索要许可；授权不清楚时不打开新控制端口或修改整份配置。

**检查点：** 一个已知手机测试请求出现在所选实例；规则模式有效；原本关闭的 MITM 仍关闭。无法确认接管就停止归因，不用 Mac 无关日志凑结论。

## 2. 观察广告，不按关键词直接封禁

1. 保存一次请求快照，手机空闲 15–30 秒，再保存一次，得到等长对照窗口。
2. 保存启动前快照，用户打开目标 App 并观察广告，再保存一次，记下广告出现/消失和外跳时点。
3. 重复至少两次有广告的触发。区分冷启动和后台恢复；不要为了复现卸载 App、清数据或丢失离线地图/轨迹。
4. 用 `scripts/capture_tools.py` 规范化元数据、取前后差集、汇总主机。参考命令在连接文档中。脚本输出是**候选**，不是可发布规则；无法识别结构时只检查字段名并适配，不伪造日志。

先考虑只在广告窗口重复出现且可归因于广告 SDK 的精确主机；检查已有列表及先匹配规则。广告消失也可能来自缓存、频控、断网或加载失败。

**选规则：** 优先 `DOMAIN,具体主机`。只有验证整棵子域均为专用广告服务才扩大为 DOMAIN-SUFFIX。共享 CDN、登录、地图、定位、消息、支付和内容 API 不整站封禁。IP 只用已验证独占且稳定的公网 `/32` 或 `/128`；不能封整段 CDN/ASN。Surge 假 IP（尤其 198.18.0.0/15）、私网、DNS 服务器和本机地址不是广告服务器。

HTTPS 的完整路径、响应内容在未解密时不可见；不要把不可见路径当成证据。广告与正文共用同一主机时记录“域名级无法安全分离”，不要强封。只有用户另外授权才进入限定主机的 MITM 方案；这类代码放可选模块，不塞入 list。

## 3. 单条验证并回退

先保存现有临时规则。每次只加一条 `DOMAIN,主机,REJECT` 等临时规则；它必须加在**手机实例**，不是 Mac 本机。以请求详情确认真实命中这条 REJECT，不能只看 App 没广告。CLI 命令见连接文档。

完成 A/B/A/B：正常复现广告 → 拦截后复现 → 移除该条后广告恢复 → 再拦截复现。至少两次成功阻断、一次移除后恢复；检查 App 的登录、首页、核心内容及相关功能（导航/地图/轨迹/消息/音乐/支付入口等）。不执行真实支付或发送消息来做测试。

出现功能异常立即移除**本次**规则；不 flush 其他临时规则、不清缓存来掩盖问题。只有网络请求被阻断而外跳行为没再发生，才能报告相应效果；域名过滤不能通用禁止 iOS deep link/URL scheme。

**检查点：** 候选已复现、REJECT 命中、广告受抑制、移除可恢复、核心功能通过。任一项不确定，保留为本地待验证候选，不发布进生效列表。

## 4. 更新 GitHub 和手机

验证通过才读 [仓库更新](references/repository.md)，按其中格式记录本地 evidence JSON；使用 `scripts/stage_rules.py` 暂存三个文件。它检查证据字段并保留旧规则，但不能替代真实实验。

当前请求若已要求同步 GitHub，则在授权范围内完成发布，不额外增加一轮确认。只要求分析的请求则交付候选或补丁；skill 被加载本身不构成发布授权。用最新 head/文件 SHA 防并发覆盖，保留授权外改动。

发布后读回，检查 Actions；仅刷新手机的 adgoaway 资源。先移除自己加的临时规则，再在无临时规则状态验证持久列表真实命中且 App 正常。未连接手机时只能报告仓库已更新、手机复测未完成。最后恢复临时端口、过滤器和抓包开关，保留用户原有状态。

## 交付

简要列出：目标 App/入口；观察与验证次数；最终规则；仓库提交和订阅链接；手机刷新/持久规则验证结果；回退方式。区分“观察到、推测、验证通过、尚未验证”。不要宣称所有广告或所有外跳都被阻止。

## 自检与安装

离线自检：`python3 scripts/selftest.py`。不需要手机、联网或第三方 Python 包。

在其他 Codex 环境，把本目录完整复制到 `${CODEX_HOME:-$HOME/.codex}/skills/surgeadskill/`，使 SKILL.md 位于该目录第一层。重新打开会话后用 `$surgeadskill`；例如：“用 $surgeadskill 排查两步路开屏广告，验证后同步到我的规则库。”
